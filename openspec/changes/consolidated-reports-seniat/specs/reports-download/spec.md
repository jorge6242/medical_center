# Reports Download Specification

## Purpose

Descarga de archivos generados con control de acceso y TTL (time-to-live).

## Requirements

### Requirement: Secure Download

The system MUST verify ownership before allowing file download.

#### Scenario: Download completed report

- GIVEN admin with `reports:read` permission
- AND a completed job belonging to the same tenant
- WHEN `GET /reports/jobs/:jobId/download`
- THEN returns file blob with Content-Disposition: attachment
- AND correct MIME type (application/pdf or application/vnd.openxmlformats-officedocument.spreadsheetml.sheet)

#### Scenario: Download from different tenant

- GIVEN admin from tenant A
- AND a job generated by tenant B
- WHEN `GET /reports/jobs/:jobId/download`
- THEN returns 403 Forbidden

#### Scenario: Download pending job

- GIVEN a job with status 'pending'
- WHEN `GET /reports/jobs/:jobId/download`
- THEN returns 400 Bad Request with message "Report not ready yet"

#### Scenario: Download expired report

- GIVEN a job completed 25 hours ago (TTL 24h)
- WHEN `GET /reports/jobs/:jobId/download`
- THEN returns 410 Gone with message "Report expired"
- AND file blob has been cleaned from database

### Requirement: File Storage

The system MUST store generated files in PostgreSQL with cleanup mechanism.

#### Scenario: Store generated PDF

- GIVEN worker completed PDF generation
- WHEN saving to database
- THEN stores in `GeneratedReport` table:
  - id, jobId, tenantId, format, filename, mimeType, blob (bytea), sizeBytes, status, createdAt, expiresAt
- AND expiresAt is 24 hours from createdAt

#### Scenario: Store generated Excel

- GIVEN worker completed Excel generation
- WHEN saving to database
- THEN stores blob with mimeType 'application/vnd.openxmlformats-officedocument.spreadsheetml.sheet'

#### Scenario: Cleanup cron job

- GIVEN expired reports in database
- WHEN daily cleanup runs
- THEN deletes records where expiresAt < now()
- AND frees storage space

### Requirement: Recent Jobs List

The system MUST allow listing recent jobs for the downloads sidebar.

#### Scenario: List recent jobs

- GIVEN admin with reports access
- WHEN `GET /reports/jobs?limit=10`
- THEN returns array of recent jobs:
  - jobId, status, format, filename, size, createdAt, completedAt, error
- AND ordered by createdAt desc
- AND filtered by tenantId

#### Scenario: List only active jobs

- GIVEN admin with reports access
- WHEN `GET /reports/jobs?status=active&limit=10`
- THEN returns only jobs with status in (pending, processing)

## GeneratedReport Model (Prisma)

```prisma
model GeneratedReport {
  id        String   @id @default(uuid())
  jobId     String   @unique
  tenantId  String
  format    String   // 'pdf' | 'excel'
  filename  String
  mimeType  String
  blob      Bytes
  sizeBytes Int
  status    String   // 'pending' | 'processing' | 'completed' | 'failed'
  error     String?
  createdAt DateTime @default(now())
  expiresAt DateTime
  
  @@index([tenantId, createdAt])
  @@index([expiresAt])
  @@map("generated_reports")
}
```
